# ADR-016 — SonarQube Cloud quality gate

**Status:** Accepted  
**Date:** 2026-08

## Context

The starter already validates types, local static rules, Nx dependency
boundaries and behaviour. Those tools do not provide a single, independent CI
assessment of code quality, security, duplication and coverage for pull
requests, including changes produced with AI assistance.

## Decision

Use SonarQube Cloud in CI as one project for the entire Nx monorepo. Feed it
LCOV coverage generated by Nx test targets and make the workflow wait for the
Quality Gate.

Adopt Clean as You Code. The gate applies to new code, initially requiring no
new bugs or vulnerabilities, A ratings for reliability, security and
maintainability, at least 80% coverage, and no more than 3% duplicated lines.

The integration is configured with repository-level GitHub Actions variables
and a secret rather than committing a SonarQube organization, project key or
token. This keeps the starter forkable.

## Consequences

- Pull requests receive independent quality feedback once a repository enables
  the integration.
- Historic debt does not block incremental adoption.
- SonarQube Cloud does not own architecture rules or replace existing checks.
- A new test target that produces coverage must be registered in
  `sonar-project.properties`.
